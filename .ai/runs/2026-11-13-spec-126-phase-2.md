## Decisions

- §13 had no UI copy to correct; it gains one bullet for Phase 2 (read-only hints, the G10 name
  cut) so the error-handling section covers the phase.
- The list count is one grouped statement over all artifacts (type, name, latest format,
  `having count(*) > 1`), whatever the list's filters, so a duplicate filtered out of the list
  still counts; `explain query plan` shows it walks `artifacts_type_name_idx` (pinned by a test).
- The detail list takes the group total from `count(*) over ()` on the limited query, so the 20
  rows and the total come from one statement (no unreachable fallback branch).
- The 10,000-artifact linear test uses 10,016 artifacts: `expectLinearTime` needs a multiple of
  `LINEAR_SIZE_STEP` (32).
- The full-HD test measures the same rows without and with the Badge by seeding the long
  snake_case pair with two formats and then giving the second the first's format (G17: the Name
  header width is equal).
- Stories use static data, as every pattern story does; the card model is unit-tested in
  `apps/web/test/artifacts.test.ts` and the page renders it.
