# Run: Commit shared test environment scripts

## Objective

Generate `.ai/scripts/test-env-up.sh` and `.ai/scripts/test-env-down.sh` with the
`om-prepare-test-env` skill and commit them, so later UI QA runs (`om-auto-qa-pr`, browser QA
agents) reuse them instead of regenerating them each run.

## Plan

1. Worktree `.ai/tmp/test-env-scripts` on `chore/test-env-scripts` from `origin/main`.
2. Follow `om-prepare-test-env` phase 2: discover the run recipe, write the scripts, verify.
3. Verify cold, warm, down, down twice, cache invalidation; lint.
4. Commit, open a PR, review with `om-auto-review-pr`.

## Decisions

- **Built CLI, not `next dev`:** the scripts boot the app exactly as `apps/web/playwright.config.ts`
  does (`pnpm build`, `directivebench demo`, `directivebench serve --no-open`), with the same fake
  `claude` first on `PATH` and `ANTHROPIC_API_KEY` empty, so QA sees what users get and no real
  agent or login is touched. `serve` registers only the mock adapter.
- **Fixed port 4398** (`TEST_ENV_PORT` overrides): next to the e2e port 4399, so a QA server and
  `pnpm test:e2e` can run side by side. A port held by a process the script did not start is an
  error, never killed.
- **Data root `/var/tmp/directivebench-test-env-<cksum of checkout path>`**: per checkout, outside
  `$HOME` and every git work tree (lesson 2026-10-30-keep-heavy-data-off-tmp); the up script
  refuses any other location and writes an ownership marker, which the down script requires
  before `rm -rf`. The server's `TMPDIR` points inside it, so benchmark workspaces go with it.
- **Reuse TTL 3600 s instead of the skill's ~600 s default:** a restart reseeds the demo data, so
  a short TTL would reset the database under a QA session; a changed build input still restarts.
- **Lock only during bootstrap**, not for the environment's lifetime (deviation from the contract
  text): a lifetime lock would make every warm run wait. Rebuilding under a running server cannot
  happen through the script, because a changed fingerprint or `--force-rebuild` tears the server
  down before the build.
- **Build inputs from git**: `git ls-files -co --exclude-standard` minus `.ai/` (path, size,
  mtime) plus `NODE_ENV` and the Node.js version, so build output and ignored files never change
  the fingerprint, and run logs do not trigger rebuilds.
- **Stopping**: SIGTERM to the recorded pid only after `ps` shows it is this checkout's
  `cli.js --data-dir <root>/data serve`; members of its `setsid` process group left behind (a
  `next-server` whose parent was SIGKILLed) are signalled only when `/proc/<pid>/environ` names
  this data directory (lessons 2026-10-30-restart-a-served-build-by-port and
  2026-10-29 "never kill a pid parsed from output without checking it").
- `.gitattributes` (`*.sh text eol=lf`, `*.ps1 text`) per the skill; `.gitignore` gains the build
  cache file and lock directory (descriptor and env file were already ignored). A one-paragraph
  pointer under AGENTS.md section 6; no rule changes.

## Problems and deviations

- A first foreign-port attempt ran `cd <worktree> && node … &`, which put the `cd` in the
  background subshell, so the next commands ran in the main checkout and created a test lock
  there; it was removed at once, and the stray test listener was stopped by its verified pid.
- Contract deviations: lock scope and TTL default (see Decisions); no credentials file (the app has
  no authentication).

## Review

`om-auto-review-pr 182`, round 1 (posted as a comment; GitHub does not let the author request
changes on their own PR): one major and one minor, both fixed in a follow-up commit.

- Major: a failure after `serve` was launched (health timeout, identity check, home probe) exited
  without stopping it and before any descriptor named its pid, so neither script could find it
  later. The up script now writes a `starting` descriptor right after the launch and runs the down
  script on every failure after it. New `TEST_ENV_READY_TIMEOUT_SECONDS` (default 120) made the
  path testable.
- Minor: `serve` takes `DIRECTIVEBENCH_HOST` from the environment when `--host` is missing; the
  script now passes `--host 127.0.0.1`.

Full gate on the PR head: `format:check`, `lint`, `typecheck`, `build`, `verify:pack` passed;
`pnpm test` failed once in `packages/core/test/linear-time.test.ts` (timing ratio 0.338 vs 0.286
under load from a parallel agent) and passed 7/7 tasks on the rerun. The diff has no TypeScript.
