# SideBySideDiff

`import { SideBySideDiff } from '@/components/output-files/side-by-side-diff'`

**Proposed for SPEC-123 (assumption A14), awaiting the maintainer's approval.** No page uses it
yet; the compare page (Phase 4) and the blind review (Phase 5) are planned.

## 1. Purpose

Shows the same path written by two agent runs side by side, aligned by a bounded line diff, so
a reader sees what changed between baseline and candidate, or between A and B in a blind review.
Source: SPEC-123 FR-123-30 to 32, A12.

## 2. When to use

- `/results/[id]/compare`: two agent runs of one case, named by variant and repetition.
- `/results/[id]/blind-review`: sides "A" and "B" with `variant="neutral"`.

## 3. When not to use

| Situation                               | Use instead                         |
| --------------------------------------- | ----------------------------------- |
| One file                                | `FileView`                          |
| Two scores or verdicts                  | The RED/GREEN result pattern        |
| Versions of an artifact in the registry | Not built (a code editor, SPEC-109) |

## 4. Anatomy

1. Header: the path (`h3`, `font-mono`) and one `role="status"` sentence from `diffSummary`.
2. Two columns, each with an `h4` ("Left: Baseline (v2), repetition 1", or "A"), its notices
   (as in `FileView`) and a named scroll region.
3. Rows: line number, a marker column and the text. A changed line has a tint, a visible
   marker and a screen-reader label; a filler row (`bg-muted`, no number) keeps the sides
   aligned where one side has lines the other lacks. Within a run of changes, removed and added
   lines are paired row by row.

## 5. Variants

| `variant`          | Marker and label (left / right)   | Tint                            | Use          |
| ------------------ | --------------------------------- | ------------------------------- | ------------ |
| `change` (default) | `-` "Removed" / `+` "Added"       | `destructive/10` / `success/10` | Compare page |
| `neutral`          | `<` "Only in A" / `>` "Only in B" | `info/10` on both sides         | Blind review |

The neutral variant has no red or green: in a blind review, colour must not suggest that one
side is worse.

## 6. States

| State                                | Summary line                                                                         |
| ------------------------------------ | ------------------------------------------------------------------------------------ |
| Changed                              | "3 lines removed, 5 lines added." (neutral: "3 lines only in A, 5 lines only in B.") |
| Identical                            | "The files are identical." (no markers)                                              |
| Only additions or deletions          | "2 lines added." or "2 lines removed."; the other side gets filler rows              |
| Over the bound (1,000 changed lines) | "These files differ in more than 1,000 lines, so they are shown without alignment."  |
| One side missing or not kept         | "No line comparison: one side has no text to compare."; that side says why           |

## 7. Accessibility

- Changes are never colour alone (SPEC-123 FR-123-32, WCAG 1.4.1): a visible marker and an
  `sr-only` label ("Removed:", "Added:", "Only in A:") start each changed line; the marker
  glyph itself is `aria-hidden`.
- Each column is a named tab stop ("Left: src/render.php") for horizontal scrolling.
- Marker colours are the measured `*-foreground` tokens on their `*/10` fills (Colour page).

## 8. Content

- Side names are short ("Left", "Right", "A", "B"); the description says who produced the
  side. In a blind review, pass no description: it would reveal the variant.
- Counts use "line" or "lines" and en-US digit grouping ("1,000").

## 9. Responsiveness

A container query (`@3xl`, 48rem of the component's own width) puts the columns side by side;
narrower, they stack, left first. Lines scroll inside each column; nothing scrolls the page
sideways at 320px.

## 10. API

<ArgTypes of={Stories} />

`left` and `right` are `{ name, description?, file: OutputFile | null }`. The diff runs in render
(`diffLines` in `lib/line-diff.ts`): Myers after trimming the common start and end, stopped at
`FILE_DIFF_MAX_EDIT_LINES` (1,000 removed plus added lines).

## 11. Code

```tsx
<SideBySideDiff
  path="src/render.php"
  left={{ name: 'Left', description: 'Baseline (v2), repetition 1', file: left }}
  right={{ name: 'Right', description: 'Candidate (v3), repetition 1', file: right }}
/>

<SideBySideDiff path={path} variant="neutral" left={{ name: 'A', file: a }} right={{ name: 'B', file: b }} />
```

## 12. Do and don't

| Do                                                     | Don't                                              |
| ------------------------------------------------------ | -------------------------------------------------- |
| `variant="neutral"` and no description in blind review | Red and green, or variant names, before the reveal |
| Say in words when there is no alignment                | Silently show two unaligned files                  |
| Keep notices of each side above its column             | Hide that a side was truncated                     |

## 13. Related

`FileView`, `FileStatusBadges` ("Only left" in a path list), `NativeSelect` (choosing the two
agent runs), the Risky-action pattern ("Reveal variants").
